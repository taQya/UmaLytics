# 🐴 競馬 予想チャットくん v3(中央・地方対応/Windows GUI)

出馬表CSV(`*_horselist.csv`)を読み込み、競馬場×レースごとの勝ち馬を予想チャット風に表示するWindows向けGUIアプリです。**中央競馬(JRA)と地方競馬(NAR)の両方に対応**しています。**Python標準ライブラリ(tkinter)のみ**で動作するため、追加インストールは不要です。

## 起動方法(Windows)

1. [python.org](https://www.python.org/downloads/) のPythonをインストール(標準設定でtkinter同梱)
2. `keiba_yosou_gui.py` を**ダブルクリック**、またはコマンドで:

```bat
python keiba_yosou_gui.py
```

## 画面の使い方

1. **[📂 出馬表CSVを開く]** で `*_horselist.csv` を選択
   → 同じフォルダの `*_racelist.csv`(レース名・発走時刻)と `*_payback.csv`(払戻)は**自動検出**
2. 必要なら **競馬場・レース**のプルダウンで絞り込み
3. **[🏇 予想実行]** → 左にレース一覧が表示される
   - 行の色: 🟩 ◎的中 / 🟨 ◎が3着以内(複勝圏) / 🟥 外れ / 白 = 未終了レース
4. レースをクリックすると右側に**チャット風の予想詳細**(◎○▲△☆の印・根拠・参考買い目・結果)を表示
5. **[💾 テキスト保存] / [💾 JSON保存]** で全レースの予想を出力
6. 下部ステータスバーに答え合わせの集計(◎的中率・単勝100円買いの回収率)を表示

## 予想ロジック(レース前情報のみ使用)

horselist内の「着順」「タイム」列は結果データなので**予想には使いません**。基準50点から以下で加減点します。

- **全成績**(「1着-2着-3着-着外」形式を自動パース): 通算勝率×40点+複勝率×20点(10走未満は信頼度を按分)
- **JRA所属加点**(交流重賞での実力差を考慮): 騎手所属・調教師所属の欄に「JRA」(または栗東/美浦のトレセン表記)が含まれる馬に+8点。地方所属馬には加点なし。係数はパラメータ`jra_affili`で調整・学習可能
- **近走成績**(前走/2走前/3走前着順の列があれば): 前走>2走前>3走前の重みで1着+8×重み〜二桁着順は減点
- **出馬表ページ由来の近走**(`deba_table.py`で取得した場合): 地方競馬のhorselist CSVには前走以前の列が無いため、出馬表ページから過去5走を集めて評価します。着順点(`deba_recent`)に加え、**着差**(`deba_margin`)・**上がり3F**(`deba_agari`)・**コーナー通過順から見た先行力**(`deba_pace`)はレース内で標準化して比較、さらに**レース間隔**(`deba_interval`)と**継続騎乗**(`deba_jockey`)を加減点します
- **当競馬場・当距離成績**: 各 勝率×15点+複勝率×8点(3走以上で評価)
- **騎手成績**: 勝率25%以上+8点、15%以上+4点。「☆580」等の減量騎手表記は自動認識して+2点
- **人気**: 1番人気+12点 〜 10番人気以下-8点
- **馬体重増減**: 体重比2%以上の変動で-5点(ばんえいの1000kg級にも対応)
- **負担重量**: レース内平均比1%重いごとに約-2点
- **年齢**: 8歳以上で軽い減点

1位と2位の点差から信頼度S(鉄板級)〜C(混戦・波乱注意)を判定します。重み付けは `score_horse()` 関数にまとまっているので調整も簡単です。

## 🏛 中央競馬(JRA)対応

同じCSVフォーマットで中央競馬のデータを読み込めば、**競馬場名から自動でJRA/地方を判定**して中央モードで予想します(サンプル: `sample_jra_horselist.csv` / `sample_jra_racelist.csv`)。

**自動判定される中央競馬場**: 札幌・函館・福島・新潟・東京・中山・中京・京都・阪神・小倉(それ以外は地方として扱います)

**中央モードでの違い**

- 🏛バッジと【中央】表示でひと目で区別。中央・地方のデータを1つのCSVに混在させてもOK
- **馬場適性評価**: racelistの「芝ダート区分」「回り」と、horselistの「芝左成績」「芝右成績」「ダート左成績」「ダート右成績」列を突き合わせ、当該コースの成績(勝率×15点+複勝率×8点)を加点。例えば東京(芝・左回り)なら「芝左成績」を参照します。回りが不明・直線の場合は左右を合算して評価
- **期待値計算の払戻率切替**: 単勝の払戻率を中央80%(控除率20%)/地方75%で自動的に使い分け、推定オッズと期待値の精度を向上

**中央競馬用CSVの追加列(任意)**: `芝左成績`, `芝右成績`, `ダート左成績`, `ダート右成績`(いずれも「1着-2着-3着-着外」形式)。racelist側は `芝ダート区分`(芝/ダート)と `回り`(右/左)。これらが無くても他のファクターだけで予想は動きます。


## 🏇 地方競馬データの自動取得

GUIの **[🏇 地方データ取得]** ボタン、または `download_race_data.py` で、地方競馬情報サイト(keiba.go.jp)から当日の出走データZIPをダウンロード→`horselist` フォルダに解凍→出馬表CSVを自動検出して読み込みます。

```bat
python download_race_data.py             # 本日分
python download_race_data.py 2026-07-05  # 日付指定
```

`requests` が入っていればそれを使い、無ければ標準ライブラリ(urllib)で動作します。ボタンを押すとダウンロードから予想までワンストップで進みます。

**注意**: ダウンロードのパラメータ(`params` の `k_raceDate` 等)は取得サイトの仕様に合わせて調整が必要な場合があります。ZIPでなくHTMLフォームを取得してしまった場合は、その旨のエラーを表示するので、ブラウザのNetworkタブで実際のリクエストを確認して `download_race_data.py` の `params` を調整してください。ダウンロードできるのは**当日分のみ**で、日付を指定しても過去分は取得できません。個人利用の範囲で、サイトの利用条件をご確認の上ご利用ください。

## 📋 出馬表データの収集(CSVに無い馬情報)

地方競馬のhorselist CSVには**前走以前の情報が1列も入っていません**。そのため近走評価が効かず、実力が近い馬同士の比較ができませんでした。`deba_table.py` は出馬表ページから、CSVに無い以下の情報を集めます。

- 過去5走の **着順 / 日付 / 馬場 / 頭数 / 競馬場 / 芝ダート / 回り / 距離 / 馬番 / レース名**
- 過去5走の **走破タイム / コーナー通過順 / 上がり3F / 着差 / 勝ち馬 / 人気 / 馬体重 / 騎手 / 斤量**
- 当日の **枠番 / 単勝オッズ / 人気 / 馬体重増減 / 最高タイム**

GUIの **[📋 出馬表データ取得]** ボタン、またはコマンドで取得します。

```bat
python deba_table.py horselist/20260810_horselist.csv     :: 1日分
python deba_table.py horselist/*_horselist.csv            :: まとめて(過去分も可)
```

- 取得結果は horselist と同じフォルダの `deba_YYYYMMDD.json` にキャッシュされ、以後は**通信なし**で予想に使われます(取得済みレースは再取得しません)
- サーバー負荷防止のため1レースにつき1秒待機します(1日あたり40〜50レースで約1分)
- `download_race_data.py` と違い**過去日も取得できる**ので、`tune_params.py` の学習データを一気に厚くできます
- 中央競馬(JRA)は対象外です

これで作られる指標は「近走の着順点」「着差」「上がり3F」「コーナー通過順から見た先行力」「レース間隔」「継続騎乗」の6つで、着差・上がり・先行力はレース内で標準化してから比較します。重みは `keiba_params.json` の `deba_*` で、`tune_params.py` から自動調整できます。

## 🗄 馬データベース(生涯成績・血統の蓄積)

`deba_table.py` の出馬表ページは直近5走までだが、keiba.go.jp には馬ごとに**生涯の全レース履歴**と**血統・生産者・馬主などのプロフィール**を見られるページがある。`horse_db.py` はここから取得してSQLite(`horses.sqlite3`)に蓄積する。

```bat
:: 1) 血統登録番号を集める(通信なし。deba_table.pyのキャッシュから収集)
python horse_db.py --seed

:: 2) 未取得/古い馬のデータを取得してDBに追加(1頭2リクエスト・1秒間隔)
python horse_db.py --fetch
python horse_db.py --fetch --limit 200      :: 様子見に件数を絞る

:: 状況確認(引数なし)
python horse_db.py
```

- `horses` テーブル: 生年月日・毛色・調教師(所属)・馬主・産地・生産牧場・3代血統(父/父父/父母/母/母父/母母)・収得賞金
- `races` テーブル: 生涯の全レース(日付・競馬場・レース名・格・距離・天候・馬場・頭数・枠番・馬番・人気・着順・タイム・着差・上がり3F・馬体重・騎手(所属)・斤量・調教師・収得賞金・1着馬/2着馬)
- 勝率や距離別成績などの集計値は持たない。`races` テーブルにSQLで問い合わせれば計算できるため(例: `SELECT track, COUNT(*), AVG(chaku<=3) FROM races WHERE lineage_code=... GROUP BY track`)
- 既に新鮮なデータ(既定7日以内に取得済み)がある馬は自動でスキップするので、2回目以降は差分だけで済む
- 初回は血統登録番号の数に応じて数時間かかる(例: 7000頭で約4時間)。中断しても再実行すれば続きから取得する

現時点では予想スコアには使っていない参考データベース。血統・生産者・距離別成績など、`deba_table.py` の6指標とは別軸の特徴量を今後追加する際の土台になる。

**注意**: 血統登録番号は地方競馬の出馬表ページ経由でしか集めていないため、このDBに入るのは「地方競馬の出馬表に登場した馬」に限られる。それらの馬がJRA交流競走で走った記録(トラック名が「Ｊ○○」表記)は含まれるが、地方に一度も来ない純粋なJRA所属馬のデータは対象外。

### 毎日の自動更新

`horse_db.py --daily` は、その日の地方競馬データを取得 → 出馬表データ収集 → **その日出走した馬(+初見の馬)だけ** をDBに反映する。`--fetch`(7日以上古い馬を一律再取得)と違い、毎日回しても取得件数がまとまって膨れ上がらない。

**注意(robots.txt)**: keiba.go.jp の `robots.txt` は `Crawl-delay: 10` を指定しており、かつ本ツールが使う `/KeibaWeb/TodayRaceInfo/` `/KeibaWeb/DataRoom/` `/KeibaWeb/DataDownload/` を全bot対象に明示的に `Disallow` している。これに合わせて `deba_table.py` の `SLEEP` は10秒にしてある(以前は1秒だったが変更済み)。1日あたり出走馬300〜500頭として**2〜3時間程度**かかる計算になるので、深夜〜早朝の時間帯に実行することを想定している。クラウド等この端末以外での実行は行わない(データセンターIPは検知・遮断されやすい上、そもそもrobots.txtが禁止しているページへの自動アクセスである点は場所によらず変わらないため)。

```bat
python horse_db.py --daily
```

`run_horse_db_daily.bat` をタスクスケジューラに登録すれば自動化できる(地方競馬は開催場により21〜22時頃まで走るため、23時以降を推奨):

```bat
schtasks /create /tn "KeibaHorseDBDaily" /tr "C:\keiba\run_horse_db_daily.bat" /sc daily /st 23:00
```

## 🌐 JRA公式サイトからの自動取得(実験的機能)

`fetch_jra.py` を同じフォルダに置くと、GUIの **[🌐 JRAから取得]** ボタン、またはコマンドで今週のJRA出馬表を取得してCSV化できます。

```bat
python fetch_jra.py                 # 今週の全レース → jra_YYYYMMDD_horselist.csv 等
python fetch_jra.py --place 東京    # 競馬場で絞り込み
python fetch_jra.py --debug         # 取得HTMLを保存(構造変更時の調査用)
```

**取得の仕組み**: JRAサイトの出馬表はURL固定ではなく、画面のdoAction()と同じ **POST方式(cname=…)** でアクセスします(GETの`?CNAME=`はパラメータエラーになることを実サイトで確認済み)。開催選択ページのレースリンクを起点に、各レースページ内のリンク(同開催の1〜12R・他場のレース)を芋づる式に辿る**BFSクロール**で全レースを収集します。`--date 20260705` で対象日を指定でき、省略時は本日以降のみ取得します。

**取得できる項目**(2026年7月の実ページで検証済み): 馬番/馬名/性齢/騎手/負担重量/**単勝オッズ/人気**/**通算成績**/**過去3走の着順**/馬体重(当日発表後)/取消・除外の状態と、レースの 場名/レース名/発走時刻/芝ダート/回り/距離。**通算成績と近走着順が取れるため、予想エンジンの実力評価・近走評価がフルに機能します。**

**実オッズで期待値計算**: 取得CSVには単勝オッズ列が含まれるため、期待値買いは人気からの推定ではなく**実オッズで計算**されます(画面に「実オッズ」と表示。オッズ未発表の時間帯は従来通り推定)。

**⚠️ 必ずお読みください**
- ナビゲーション(POST方式・BFSクロール)と出馬表ページの解析は、実サイトから取得したHTML(2026年7月・北九州記念ほか)で検証済みです。ただしサイト構造は予告なく変更されるため、サイトのHTML構造は予告なく変更されるため、取得に失敗する場合は `--debug` でHTMLを保存し、`fetch_jra.py` 内の正規表現を調整してください
- JRA公式サイトの**利用規約・robots.txtを確認**の上、個人利用の範囲でお使いください。リクエスト間隔(1.5秒)は短くしないでください。継続的・大量のデータ利用には公式のJRA-VANデータラボをご検討ください
- オッズは取得時点のものです。締切まで変動します


## 🏁 結果の自動取得と 📈 結果からの学習

**結果取得**: GUIの **[🏁 JRA結果取得]** ボタン、または `python fetch_jra.py --results` で本日のレース結果(1〜3着馬番・単勝/複勝払戻)を取得し、payback CSVとして保存します。出馬表を読み込んでいれば自動で答え合わせ付きの再予想が走り、◎的中率・回収率が表示されます。※結果ページのHTML構造は未検証のため、失敗時は `--debug` のHTMLで調整が必要になる場合があります(出馬表のときと同じ手順)。

**結果から学習(パラメータ自動調整)**: 予想と結果の差異を使って、エンジンの重み(通算成績・近走・適性・騎手・人気・斤量・勝率変換の温度)をランダムサーチで最適化し、`keiba_params.json` に保存します。両アプリは起動時にこのファイルを自動で読み込みます。

```bat
python tune_params.py jra_20260705_horselist.csv                # 1日分
python tune_params.py day1_horselist.csv day2_horselist.csv     # 複数日まとめて(推奨)
python tune_params.py *_horselist.csv --objective recovery      # 回収率を最大化
```

GUIでは **[📈 結果から学習]** ボタンで実行でき、学習後は自動で再予想して改善を確認できます。元に戻すには `keiba_params.json` を削除してください。

**⚠ 過学習に注意**: 1日分(数十レース)だけで調整すると「その日に合わせすぎた」パラメータになり、翌週はむしろ悪化することがあります。horselist+paybackのペアを週ごとに貯めて、複数週まとめて学習するのがおすすめです。表示される改善は学習データ上(イン・サンプル)の数字で、未来の的中を保証しません。

参考: 2026/7/4の地方9レースで学習した場合、学習データ上では ◎的中1/9→3/9、◎3着以内4/9→7/9、期待値買い回収率220%→330% に改善しました(あくまでイン・サンプル)。



## 🧊 exe化(コマンド1つでWindows実行ファイルを作る)

Pythonが入っていないPCでも動く単一の `.exe` を作れます。以下のファイルを同じフォルダに置いて、**`build_exe.bat` をダブルクリック**するだけです。

- `build_exe.bat`(ビルド用バッチ)
- `keiba_yosou.spec`(PyInstaller設定)
- 全 `.py` ファイル(`keiba_yosou_gui.py` ほか)

```bat
build_exe.bat        :: これ1つでOK(PyInstallerが無ければ自動インストール)
```

完成すると `dist\競馬予想チャットくん.exe` ができます。ダブルクリックで起動でき、コンソール窓は出ません。

**仕組み・ポイント**
- GUIが実行時に動的importする `fetch_jra` / `spat4_bet` / `tune_params` / `download_race_data` / `post_wordpress` / `keiba_yosou` は、specの `hiddenimports` で全て同梱されます(単一exe・約20MB)
- `keiba_params.json`(学習結果)やCSV・投票リストは、**exeと同じフォルダ**を基準に読み書きします。exeの隣に `horselist` フォルダや `keiba_params.json` を置けばそのまま使えます
- アイコンを付けたい場合は `keiba.ico` を用意し、`keiba_yosou.spec` の `icon="keiba.ico"` の行のコメントを外して再ビルドしてください

**注意**: exeはビルドしたOS向けにしか作れません(Windowsで作ればWindows用)。手元のCSV取得系(`download_race_data.py`)は `requests` が無くても標準ライブラリで動くため、追加ライブラリなしでビルドできます。

## 📰 WordPressへの毎日自動投稿

`post_wordpress.py` で予想記事をWordPressに自動投稿できます(標準ライブラリのみ)。

**初期設定(1回だけ)**
1. WordPress管理画面 → ユーザー → プロフィール → **アプリケーションパスワード** で新規発行(通常のログインパスワードは使いません)
2. `wp_config.sample.json` をコピーして `wp_config.json` を作成し、サイトURL・ユーザー名・アプリケーションパスワードを記入
   - ⚠ このファイルにはパスワードが入ります。自分のPCの外に出さない・共有しないでください

**使い方**
```bat
python post_wordpress.py --fetch                # JRAから当日出馬表を取得→予想記事を投稿
python post_wordpress.py --fetch --results      # 結果も取得→答え合わせ付きに記事を更新
python post_wordpress.py --csv 手元.csv --dry-run  # 投稿せずHTMLを保存して確認(推奨: 最初はこれ)
python post_wordpress.py --fetch --draft        # 下書きとして投稿
```

**手元CSVの日付は自動解決できます**(毎日のコマンドを固定にできる):

```bat
python post_wordpress.py --csv ./houselist                              # フォルダ指定→今日の日付のファイルを自動選択
python post_wordpress.py --csv ./houselist/jra_{today}_horselist.csv    # {today}が今日のYYYYMMDDに置換される
python post_wordpress.py --csv ./houselist --date 20260705              # 日付を明示指定(過去分の再投稿など)
```

**中央・地方の両フォーマットに対応**しています。フォルダ内に中央(`jra_YYYYMMDD_horselist.csv`)と地方(`YYYYMMDD_horselist.csv`)の両方があれば、それぞれ**別記事**として投稿されます。タイトルは競馬場から自動判定(【中央競馬AI予想】/【地方競馬AI予想】/混在なら【中央・地方競馬AI予想】)され、スラッグも `keiba-yosou-YYYYMMDD-jra` / `-nar` / `-all` と分かれるため、上書き更新が互いに干渉しません。

ファイルパスを直接指定した場合も、ファイル名内の日付(jra_**20260705**_horselist.csv / **20260705**_horselist.csv)を自動検出して記事タイトル・スラッグに使うため、前日夜に実行しても記事は正しい開催日の日付になります。当日ファイルが無い場合はフォルダ内の候補一覧を表示して終了します。

記事にはレースごとの印(◎○▲△☆)テーブル・本命の根拠・参考買い目・期待値買い、`--results` 時は答え合わせ(◎的中率・回収率)が入ります。スラッグ `keiba-yosou-YYYYMMDD` で同日の既存記事を検索して**上書き更新**するため、「朝に予想投稿→夜に答え合わせ更新」と2回実行しても記事は1日1本に保たれます。記事末尾には「参考情報・20歳以上・自己責任」の注意書きが自動で入ります。

**毎日の自動実行(Windowsタスクスケジューラ)**
同梱の `run_daily.bat` を使い、管理者コマンドプロンプトで:
```bat
schtasks /create /tn "KeibaYosou朝" /tr "C:\keiba\run_daily.bat" /sc daily /st 09:00
schtasks /create /tn "KeibaYosou夜" /tr "C:\keiba\run_daily.bat results" /sc daily /st 18:00
```
(パスはご自身の配置場所に合わせてください。開催日以外は「レースが見つからない」旨のエラーで終了するだけで害はありません)

**注意**: 予想記事の公開はご自身のサイトの責任で行ってください。JRAのデータ取得に関する注意(利用規約・アクセス間隔)は前述の通りです。


## 🎫 SPAT4 投票リスト生成(自動投票の下書き)

期待値が**しきい値を超えた単勝**だけを抽出し、資金管理を適用した投票リストを出力します。GUIの **[🎫 SPAT4投票リスト]** ボタン、または `spat4_bet.py` で実行できます。

```bat
python spat4_bet.py 20260704_horselist.csv --ev 130 --unit 200 --budget 3000
python spat4_bet.py jra_20260705_horselist.csv --ev 110 --stake kelly --bankroll 50000
python spat4_bet.py ./houselist --date 20260705    # フォルダ+日付指定
```

出力は2種類(入力と同じフォルダ): `spat4_bets_YYYYMMDD.txt`(人が読む投票指示)と `spat4_bets_YYYYMMDD.csv`(表計算・マークカード転記用)。

**資金管理**
- `--stake flat`(既定): 1点あたり `--unit` 円の定額
- `--stake kelly`: ケリー基準の比例配分(`--bankroll` 総資金 × フラクショナルケリー係数 `--kelly-frac`、既定0.25=1/4ケリー)。過大ベットを抑える安全側の設定です
- `--budget`: 1日の上限予算。期待値の高い順に予算内で採用し、超過分は自動カット。**使いすぎ防止のため必ず設定を推奨**

**⚠ 重要な制約(安全のための設計)**
- このツールは**投票リスト(下書き)を作るところまで**です。SPAT4サイトへのログイン・購入の確定は**必ずご自身で**行ってください
- 加入者番号・利用者ID・暗証番号・P-ARS番号などの**認証情報は一切扱わず、自動入力もしません**。金融口座の認証をプログラムに任せるのは規約違反・不正利用・アカウント凍結のリスクがあるためです
- ネット投票サービスは自動化ツールによるアクセスを規約で制限している場合があります。生成物は「手入力の下書き」としてお使いください
- **推定オッズのデータ**(人気からの概算)では期待値が過大に出やすく、実オッズと大きくズレます。`fetch_jra` で取得した**実オッズ付きデータ**ほど精度が上がります。投票前にSPAT4で実オッズを必ず確認してください
- 馬券は20歳以上・自己責任で、1日の上限予算を設定し、余裕資金の範囲でお楽しみください


## 🔒 予想の確定(オッズ変動で予想がブレない仕組み)

人気・オッズは締切まで変動するため、データを取得し直すたびに予想(印)が変わってしまう問題への対策です。

- その日の予想を**最初に実行した時点で自動確定**し、`yosou_fixed_YYYYMMDD.json`(horselistと同じフォルダ)に保存します
- 以後、同じ日のデータを何度取り直して[予想実行]しても、**印・順位・信頼度は確定時点のまま固定**されます(ステータスバーに 🔒確定済み と表示)
- ただし**期待値買いだけは最新オッズで毎回再計算**されます。「予想は固定・買う価値の判断は直前オッズで」という運用が自動で実現されます
- 予想を作り直したいときは **[🔓 予想を再確定]** ボタン(確定ファイルを破棄して最新データで確定し直し)
- 確定後に出走取消となった馬は自動で除外されます

この仕組みにより、人気係数(`ninki`)を使った的中率の高い予想を、安定した形で運用できます(デフォルトを1.0に戻しました)。人気を使いたくない場合は `keiba_params.json` で `"ninki": 0` にしてください。

## 💰 期待値買い機能

「的中率×配当が100%を超える見込みの買い目」を自動抽出します。

**仕組み**
1. モデルスコアをレース内softmaxで**推定勝率**に変換
2. 人気順位から市場支持率(Zipf近似)を求め、払戻率75%で割って**推定オッズ**を算出
3. **期待値 = 推定勝率 × 推定オッズ**。閾値(デフォルト100%)以上の馬だけ単勝で買い(最大2点)、届かないレースは**「見送り」**
4. payback.csvがあれば、この戦略の的中数・投資額・回収率を自動でバックテスト

**使い方**: GUIでは画面上部の「期待値閾値」で調整して[予想実行]。CLIでは `--ev 120` のように指定。閾値を上げるほど買うレースが減り、厳選されます。

**2026/7/4の終了9レースでのバックテスト結果(閾値100%)**: 18点購入・的中2・投資1,800円→払戻3,960円(**回収率220%**)。6番人気3,150円などの中穴を拾えました。

**⚠️ 重要な注意**
- 9レースは統計的に極めて小さいサンプルです。この回収率が今後も続く保証は全くありません
- 推定オッズは人気からの概算です。**購入直前に実オッズを確認**し、推定より大幅に低い場合は期待値が成立しません
- 地方競馬は控除率約25%のパリミュチュエル方式のため、長期的に回収率100%超を保証する手法は存在しません。期待値100%超は「モデル上の見込み」です
